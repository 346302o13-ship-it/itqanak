# بوابة الطالب

بوابة المرحلة الثالثة عربية RTL وتعمل بجلسات الخادم وصلاحيات RBAC من المرحلة الثانية.
جميع صفحاتها ديناميكية وغير قابلة للفهرسة، ولا ترسل بيانات كل الطلبات إلى المتصفح لتنفيذ
بحث أو تصفية محليين.

## الصفحات

| المسار                                 | الوظيفة الحالية                                                         |
| -------------------------------------- | ----------------------------------------------------------------------- |
| `/ar/student`                          | أعداد الطلبات النشطة والتي تحتاج رد الطالب والمكتملة، وآخر خمسة طلبات.  |
| `/ar/student/requests`                 | قائمة الطلبات مع بحث وتصفية وترتيب وتقسيم صفحات على الخادم.             |
| `/ar/student/requests/new`             | اختيار خدمة فعالة وحفظ طلب جديد كمسودة.                                 |
| `/ar/student/requests/[requestNumber]` | التفاصيل، وتعديل المسودة، والمرفقات، والإرسال أو الإلغاء، والخط الزمني. |

تعرض قائمة الطلبات 20 عنصرًا افتراضيًا وبحد أقصى 50. يدعم البحث رقم الطلب أو العنوان،
والتصفية بالحالة والخدمة، والترتيب بالأحدث أو الأقدم أو أقرب موعد. تستخدم الاستعلامات
فهارس المالك والحالة والتاريخ، وتظل كل predicates مقيدة بمعرف الطالب.

## رحلة الطالب

1. يختار الطالب خدمة فعالة من الكتالوج العام أو من نموذج الطلب.
2. يحفظ مسودة بمفتاح إرسال UUID يحمي من النقر أو إعادة الطلب مرتين.
3. يكمل العنوان والوصف والحقول الاختيارية ويحفظ تعديلات المسودة.
4. يرفع ملفات إذا كانت سياسة الخدمة تسمح بها، ويرى حالة التخزين والفحص لكل ملف.
5. يوافق على نسخة سياسة النزاهة الحالية ويرسل الطلب.
6. يستطيع إلغاء `DRAFT` أو `SUBMITTED`، ويرى بعد كل تغيير خطًا زمنيًا من الأحداث
   المهيكلة.

لا توجد في هذه المرحلة محادثة أو عرض سعر أو دفع أو تسليم أو شاشة إدارة طلبات. تظهر صفحة
الإدارة المحمية الموجودة من المرحلة الثانية فقط، وتأتي إدارة الطلب في المرحلة الرابعة.

## المرفقات في الواجهة

تعرض الواجهة `PENDING_SCAN` كملف ينتظر الفحص، و`INFECTED` كمرفوض أمنيًا، و`SCAN_ERROR`
كتعذر فحص. عند `FILE_SCAN_MODE=disabled` تعرض بوضوح «لم يُفحص — بيئة تطوير»، ولا تصفه
بالآمن. تسمح بيئة غير إنتاجية فقط بتنزيل `SCAN_SKIPPED_DEVELOPMENT` مع ترويسة تحذير؛
الإنتاج لا يسمح إلا بـ`CLEAN`.

الرفع يرسل الملف كبث خام ولا يستخدم اسم الملف كمسار تخزين. تحدد الصفحة الحد الفعلي كأصغر
حد بين إعداد المنصة وسياسة الخدمة. راجع [`FILE_UPLOADS.md`](./FILE_UPLOADS.md) و
[`FILE_SCANNING.md`](./FILE_SCANNING.md).

## الأمان وتجربة الخطأ

- تتطلب الصفحات principal طالبًا وصلاحية العملية، وتتحقق APIs مرة أخرى؛ إخفاء زر ليس
  تفويضًا.
- كل POST محمي بفحوص Host/Origin وCSRF ونوع المحتوى الملائم.
- كل تعديل يحمل `version`; تعرض الاستجابة تعارضًا بدل فقد تعديل متزامن.
- الطلب أو المرفق المملوك لطالب آخر يعامل كغير موجود لمنع IDOR وتسريب الوجود.
- الاستجابات والصفحات الخاصة تستخدم `no-store`، والتنزيل يستخدم
  `application/octet-stream` و`nosniff` وCSP sandbox واسمًا آمنًا في
  `Content-Disposition`.
- صفحات الطالب والإدارة محظورة في `robots` ولا تدخل sitemap؛ صفحات الكتالوج العامة فقط
  قابلة للاكتشاف.

## حالة الصفحة بعد عمليات العامل

فحص الملف عملية غير متزامنة وقد يرفع `version` الطلب بعد تحميل الصفحة. إذا عاد
`VERSION_CONFLICT` عند تعديل أو حذف لاحق، يجب تحديث صفحة التفاصيل ثم إعادة القرار على
النسخة الحالية. لا تعيد الواجهة إرسال mutation قديمة تلقائيًا.
